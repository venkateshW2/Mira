### Dataset shape
- 4.21 h total, 38 files, min 60 s / avg 399 s / max 1106 s.
- 34 of 38 are longer than the 120 s clip length — **this is fine, not a problem** (see
  "Why long files are OK" below).
- Caption diversity: 38 distinct prompts, 12 genres, 22 mood sets, 38 instrument sets.
  Style is coherent (dark ambient / experimental electronic + orchestra) — exactly the
  "one coherent style" underfit asks for.

Example sidecar:
```json
{"trigger":"zvq","TrackType":"Music","VocalType":"Instrumental",
 "genre":"Electronic: Ambient, Electronic: Experimental",
 "instruments":"synthesizer, drums, bass, piano, electric guitar, guitar",
 "moods":"film, epic, dark","bpm":"63","keyscale":"D major","length_seconds":"156",
 "prompt":"zvq, TrackType: Music, VocalType: Instrumental, Electronic: Ambient, Electronic: Experimental featuring synthesizer, drums, bass, piano, electric guitar, guitar with a film, epic, dark mood. BPM: 63. Length: 156 seconds"}
```

### Why long files are OK (the thing I checked first)
`sa3-sm-music` has `clip_duration` 120.74 s / `latent_crop_length` 1300. The worry was that
6-minute cues get truncated to their first 2 minutes. They don't:

- `pre_encode_mlx.py` encodes **whole files** up to `--max-duration` (default **600 s**),
  writing a latent-resolution `padding_mask` — no zero-pad contamination.
- `lora_train_mlx.py` takes a **random 1300-latent crop per step** (`--random-crop`, on by
  default), so a 6-min cue yields a different 120 s window every epoch.
- `lora_train_mlx.py:31`: *"seconds_total stays the FULL source duration after cropping."*
  So mira's whole-track `Length: N seconds` caption is the **correct** value for this
  pipeline, not a mismatch.

Net: all 4.21 h is usable training signal, not 38 × 2 min.

## Flags / open items

1. **Eight files exceed the 600 s pre-encode cap.** The longest is
   `I See You in My Dreams Normal` at 1106 s; 8 of 38 are over 600 s and get head-truncated,
   discarding **38.8 minutes** of audio (~15% of the set). Each truncated file still yields
   5 distinct 120 s crop windows, so the run is fine as-is — but if you want all of it,
   run `pre_encode_mlx.py` by hand with `--max-duration 1200` (CLI route below). The
   dashboard does not expose the flag, and encoder RAM at that length is untested on 16 GB.

2. **Two sidecars were hand-corrected.** mira's content-type router classified
   `Leaving Caladan` and `Ornithopter` as `stem` (both are sparse solo-instrument cues), so
   their captions read `TrackType: Instrument ... stem`. That is vocabulary the SA3 base ties
   to isolated stems, which is not what we want the LoRA to emit, so I rewrote both to
   `TrackType: Music, VocalType: Instrumental` keeping their detected genre/instruments/
   moods/bpm/key. **Re-running `mira caption --emit-sidecar` on those two will undo the
   fix** — mira has no "declare this file a track" command (`analyze --content-type` is a
   filter, not a setter). Worth a mira-side fix later.
3. **BPM is present on only 23 of 38** files — that's mira's confidence gate doing its job,
   not a bug. Better a missing BPM than a wrong one taught as fact.
4. **Free RAM.** 16 GB is tight. Before launching, check nothing heavy is running:
   `pgrep -f "VoiceStudio/project"` — quitting VoiceStudio orphans Python processes that
   ignore SIGTERM.
5. **Source of truth.** The captions came from the mira library DB (`~/.mira/library.db`),
   which indexes the **T7 copies** at `/Volumes/T7 Shield 1/DUNE_OST_SOUNDTRACK-TEST/`.
   The sidecars were generated there and copied to `datasets/dune-ost/` along with the
   audio. Both copies now carry the sidecars; the internal one is the one that trains.

## CLI route (alternative to the dashboard — same thing, more visible)

Only if the dashboard misbehaves and you want to see each stage.

```bash
cd /Users/justmac/w2app/mira/sa3-studio
source env.sh
MLX=stable-audio-3/optimized/mlx

# 1. pre-encode (writes <out>/<name>.npy + .json per file)
$MLX/.venv/bin/python $MLX/scripts/pre_encode_mlx.py \
  --audio-dir  datasets/dune-ost \
  --output-dir datasets/dune-ost-latents-same-s \
  --codec same-s --max-duration 600

# 2. train
$MLX/.venv/bin/python $MLX/scripts/lora_train_mlx.py \
  --dit sm-music \
  --dit-weights $MLX/models/mlx/dit_sm-music-base_f16.npz \
  --latents-dir datasets/dune-ost-latents-same-s \
  --lr 1e-4 --name dune-zvq \
  --adapter-type dora-rows --rank 16 \
  --batch-size 1 --max-steps 10000 --checkpoint-every 1000 \
  --latent-crop-length 1300 --random-crop \
  --demo-every 1000
```
Note `--lr` is **required** and has no default — `1e-4` is a starting point, not a
verified value for this dataset.
